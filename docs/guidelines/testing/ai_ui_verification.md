# UI-проверка при реализации

**Кому:** `implementer` для задач со строкой `UI:` в `R{NN}_tasks.md`.  
**Профиль:** [`project_quality_profile.md`](../../meta/project_quality_profile.md) D11 (ширины 360, 768, 1280).

## Когда обязательна

Задача меняет видимый UI. В плане: `UI: <маршруты> · roles: <роли> · widths: 360,768,1280`. Docs-only / tooling — `UI: n/a` или без строки.

## Предусловия (lean)

1. `npm run dev` на локальной машине.
2. Публичные маршруты — **без** логина и seed-учёток, если в `UI:` не указаны роли admin/editor.
3. Инструмент: встроенный Browser MCP или devtools; production build не запускать.

## Шаги

Для каждого маршрута и ширины из `UI:`:

1. Открыть URL на dev-сервере.
2. Установить ширину viewport.
3. Убедиться: нет ошибок в консоли, контент и ключевые состояния отображаются, нет горизонтального overflow.

При ролях из `UI:` — войти под тестовым пользователем **локально** (пароли не логировать).

## Отчёт implementer

Одна строка перед `cu-verify`:

`UI-check: <маршруты> · <роли> · <ширины> · ok`

Если dev-сервер или браузер недоступны после одного повтора — не писать `ok`; зафиксировать в открытых вопросах CU.

Отличие от `Smoke:` — smoke проверяет человек после CU; UI-check делает агент до stage.
